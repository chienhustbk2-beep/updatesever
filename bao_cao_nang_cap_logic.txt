II. DANH SÁCH FILE ĐÃ SỬA

  1. middleware.ts (GỐC)
     ────────────────────────────────────────────────────────────────────────────
     - Mở rộng matcher từ ['/admin/:path*'] → ['/admin/:path*', '/api/admin/:path*']
     - Thêm logic phân biệt page route (trả redirect) vs API route (trả JSON 401)
     - Kiểm tra JWT token qua getToken() từ next-auth/jwt
     - Nếu chưa đăng nhập (API): trả { error: "Unauthorized" } status 401
     - Nếu chưa đăng nhập (Page): redirect /login?callbackUrl=...
     - Nếu role không phải ADMIN/STAFF (API): trả { error: "Forbidden" } status 403
     - Nếu role không phải ADMIN/STAFF (Page): redirect về /

  2. src/store/useHydratedStore.ts (MỚI)
     ────────────────────────────────────────────────────────────────────────────
     - Tạo custom hook `useHydrated()` giúp chống Hydration Mismatch
     - Cơ chế: useState(false) + useEffect(() => setHydrated(true), [])
     - SSR: hydrated = false → component render với dữ liệu mặc định (0, [])
     - Client 1st render: hydrated = false → khớp với SSR → không lỗi hydration
     - Client 2nd render: hydrated = true → đọc dữ liệu thật từ Zustand store

  3. src/components/layout/Header.tsx
     ────────────────────────────────────────────────────────────────────────────
     - Thay thế useCartStore trực tiếp bằng useHydrated() để đọc cartItems an toàn
     - totalItems = hydrated ? realCount : 0 → an toàn với SSR
     - Xoá import useSyncExternalStore + hàm subscribe() không dùng đến

  4. src/app/api/webhook/sepay/route.ts
     ────────────────────────────────────────────────────────────────────────────
     - Bổ sung cơ chế IDEMPOTENCY cho webhook SePay
     - Khi nhận webhook, bên trong prisma.$transaction:
       * Kiểm tra transaction TRÙNG: cùng userId, type DEPOSIT, amount,
         description chứa content, status SUCCESS
       * Nếu đã tồn tại → return luôn (không cộng tiền lần 2)
       * Nếu chưa tồn tại → tạo transaction + increment balance (như cũ)
     - Chống: SePay gửi retry do timeout/lỗi mạng → không double-credit

  5. src/app/api/admin/transactions/route.ts (PATCH approve)
     ────────────────────────────────────────────────────────────────────────────
     - Sửa race condition: chuyển kiểm tra trạng thái PENDING vào BÊN TRONG
       prisma.$transaction thay vì kiểm tra bên ngoài
     - Cơ chế mới: đọc lại transaction bên trong transaction (txInner),
       kiểm tra status, nếu không còn PENDING thì báo lỗi
     - Chống: 2 request admin approve đồng thời → không cộng tiền 2 lần
     - Đồng thời chuyển auditLog.create vào trong transaction để đảm bảo
       atomic: nếu audit log lỗi thì toàn bộ giao dịch rollback

  6. src/app/api/admin/products/route.ts (GET)
     ────────────────────────────────────────────────────────────────────────────
     - Sửa N+1 queries (vòng lặp map gọi count từng product)
     - Cơ chế cũ: 1 query findMany + N*2 query count → O(N)
     - Cơ chế mới: 1 query findMany + 2 query groupBy → O(1)
       * availableGroups = prisma.productKey.groupBy(status: AVAILABLE)
       * soldGroups = prisma.productKey.groupBy(status: SOLD)
       * Map kết quả vào product tương ứng
     - Giảm số DB queries từ 1+2N xuống còn 3 (không phụ thuộc số lượng SP)
